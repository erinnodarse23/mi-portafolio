## El contexto

La Biblioteca Santa Lucía gestionaba su catálogo con fichas de cartón y hojas de cálculo no centralizadas: redundancia, pérdida de tiempo y sin acceso remoto. El proyecto consistió en diseñar y construir el backend de un sistema que digitalizara el control de préstamos, devoluciones y reseñas.

Nació como trabajo académico de 2º año y fue **reestructurado completamente para portafolio** con stack actualizado a las últimas versiones LTS, tests automatizados, Docker y CI/CD.

## La solución

Diseñé el modelo entidad-relación, lo normalicé hasta la Forma Normal de Boyce-Codd, lo implementé en PostgreSQL y construí una API REST con **Java 25 y Spring Boot 4.1** que expone operaciones CRUD y funcionalidades especializadas: calificación promedio por libro, consulta de préstamos por rango de fechas, usuarios con préstamos vencidos y verificación de reseñas únicas.

## Decisiones de arquitectura

- **Java 25 LTS con Virtual Threads** habilitados para mejor throughput.
- **Spring Boot 4.1.2 + Spring Framework 7 + Hibernate 7**: migración completa desde Spring Boot 3.5 / Java 17 / PostgreSQL 10.5, reduciendo el startup de ~45s a ~15s.
- **Arquitectura en 4 capas** (Controller → Service → Repository → Entity) con 6 módulos de dominio y DTOs con Java Records.
- **JPA/Hibernate sobre JdbcTemplate**: el 100% de las queries son CRUD sobre entidades con relaciones bien definidas, donde JPA brilla. (En ECASA, en cambio, usé JdbcTemplate porque eran agregaciones complejas).
- **Bean Validation en DTOs**, no en entidades, manteniendo separadas las responsabilidades de API y persistencia.
- **GlobalExceptionHandler** con distinción semántica: 400 (validación), 404 (no encontrado), 409 (regla de negocio o FK violation sin leaks), 500 (sin exponer stack traces).
- **51 tests automatizados**: 16 unitarios (JUnit 5 + Mockito) + 35 asserts E2E con smoke test contra PostgreSQL real.
- **Docker Compose** para entorno local reproducible y **GitHub Actions CI** con PostgreSQL 18.

## Stack
