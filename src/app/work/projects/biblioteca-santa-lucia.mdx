## El contexto

La Biblioteca Santa Lucía gestionaba su catálogo con fichas de cartón y hojas de cálculo no centralizadas: redundancia, pérdida de tiempo y sin acceso remoto. El proyecto consistió en diseñar y construir el backend de un sistema que digitalizara el control de préstamos, devoluciones y reseñas.

## La solución

Diseñé el modelo entidad-relación, lo normalicé hasta la Forma Normal de Boyce-Codd, lo implementé en PostgreSQL y construí una API REST con Java y Spring Boot que expone operaciones CRUD y funcionalidades especializadas: calificación promedio por libro, consulta de préstamos por rango de fechas, usuarios con préstamos vencidos y verificación de reseñas únicas.

## Decisiones de arquitectura

- **Modelo de datos normalizado hasta FNBC** (6 tablas: Autor, Género, Libro, Usuario, Préstamo, Reseña) con justificación formal del proceso de normalización y del determinante `(id_usuario, ISBN)` como clave candidata.
- **Arquitectura en 4 capas** (Controller → Service → Repository → Entity) con separación estricta de responsabilidades usando Spring Web y Spring Data JPA.
- **Reglas de negocio en la capa de servicio**: máximo 5 préstamos simultáneos, bloqueo por morosidad, disponibilidad de ejemplares, reseña única por usuario-libro y reseña posterior a la devolución.
- **DTOs con `record` de Java 17** para inmutabilidad y reducción de boilerplate.
- **Manejo global de errores** con `@RestControllerAdvice` para respuestas JSON uniformes.
- **Validaciones declarativas** con Bean Validation (`@NotBlank`, `@Min`, `@Max`) separadas del código de negocio.
- **Consultas híbridas**: métodos derivados por nombre, JPQL para agregaciones (promedio, disponibilidad) y SQL nativo para casos complejos.

## Stack

Java 17 · Spring Boot 3.2 · Spring Data JPA · Hibernate · PostgreSQL 14 · Maven · Lombok · Bean Validation · Postman
